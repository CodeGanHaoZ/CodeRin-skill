## 🧩 功能特性

### 四种工作模式

| 模式 | 用途 | 输出 |
|------|------|------|
| **A · 公众号推文** | 话题 → 三段式草稿 | 开场钩子 + 观点正文 + CTA |
| **B · AI 科技日报** | 当日 AI 动态 | 编号 + emoji + 核心要点 + 值得关注原因（≥10 条） |
| **C · 技术博客/面试题** | 技术主题/题目 | ≥2 种解法 + 复杂度对比 + 推荐 |
| **D · 话题创作** | 行业关键词/热点 | 标题备选 + 大纲 + 发布节奏 |

### 写作框架资产

- **选题矩阵**：P0/P1/P2 优先级判断标准
- **标题公式库**：悬念式 / 数字式 / 对比式 / 情绪式 / 身份代入式
- **开场钩子技术**：痛点切入 / 数字冲击 / 反常识 / 场景代入 / 直接宣言
- **公众号结构模板**：标题 → 钩子 → 三观点递进 → 结语 → 互动 CTA
- **日报标准格式**：焦点(P0) + 动态(P1) + 技术洞见 + 数据速览 + 明日关注
- **话题创作引擎**：热点捕捉路径 + 5 问质量评估表

### 内置写作红线

- ❌ 不写标题党（可夸张但需内容支撑）
- ❌ 不堆砌 AI 黑话（首次出现必须通俗解释）
- ❌ 不中立复读（有立场、有判断）
- ❌ 不无的放矢（无数据/案例不写结论）

## 🛡️ Markdown 加粗高亮兼容规范（核心特色）

这是本 Skill 最具工程化价值的部分，解决了**微信公众号等非标准渲染器下加粗断裂**的实际痛点。

### 问题根因

微信编辑器基于**不完全兼容 CommonMark** 的解析器，`**` 加粗依赖最近两个 `**` 匹配，以下字符会打断配对：

| 危险字符 | 错误写法 | 正确写法 |
|---------|---------|---------|
| 中文引号 `“` `”` | `**“自白”**` | `<strong>“自白”</strong>` |
| 英文引号 `"` | `**"confession"**` | `<strong>"confession"</strong>` |
| 百分号 `%` | `**400%**` | `<strong>400%</strong>` |
| 反斜杠 `\` | `**C:\Users\**` | `<strong>C:\Users\</strong>` |

### 规范三要点

1. **纯中英文/数字** → 正常使用 `**文字**` / `**text**` / `**123**`
2. **含任何符号** → 一律改用 HTML 标签 `<strong>...</strong>`
3. **输出前强制后处理** → 按四步管道扫描并替换，不可跳过

```
输出之前跑一遍，引号百分反斜杠，
** 包了就得换，strong 标签保平安。
```

## 🔍 验证脚本

两个脚本的差异：

| 脚本 | 扫描范围 | 适用场景 |
|------|---------|---------|
| `scripts/verify_v22.py` | 剔除代码块、行内代码后校验**正文** | **日常推荐**，判断输出是否可直接发布 |
| `scripts/verify_bold.py` | 全文扫描，但把代码块内的命中标注为 `INFO` 而非失败 | 检查含教学示例的文档 |

用法：

```bash
# 自动扫描 examples/ 下所有示例（预期全绿）
python scripts/verify_v22.py

# 扫描指定文件
python scripts/verify_v22.py path/to/your-article.md
python scripts/verify_bold.py path/to/your-article.md
```

预期输出：

```
=== article-bold-fix-v21.md（排除代码块/行内代码）===
[PASS] 正文 16 处 ** 加粗均干净
[INFO] <strong> 接管 21 处（中文引号 0 / 英文引号 1 / 百分号 14）
========================================
总计: 正文危险模式 0 处 [PASS]
```
